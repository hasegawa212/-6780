# sales-rank — 営業ランク判定エンジン

営業プレイブック9冊のうち、**判定ロジックとして書けるもの**を実装した純関数群。
資料の側に散っている基準を1か所に集め、HTMLシート・ボット・集計のどこから呼んでも
同じ答えが出る状態にする。

## なぜ作るか

同じ判定が現在3か所に散っている。

| 場所 | 何を持っているか | 問題 |
|---|---|---|
| 06 電話で聞く5問 | 電話5問 → 仮ランク | 紙。人によって解釈が違う |
| 07 アポが取れる相手 | 3軸 → 確定ランク | 紙。旧A〜C-との対応が不明 |
| ランク判定シート | 3軸の入力UI | JS に判定が直書き。検算されていない |

紙とJSに同じ基準が二重化している状態では、基準を変えたときに片方が取り残される。
**判定は1か所に置き、あとはそれを呼ぶ。**

## 設計方針

1. **純関数のみ。** I/O・状態・外部依存なし。入力を渡せば同じ答えが返る。
2. **理由を必ず返す。** ランクだけ返しても現場は納得しない。
   「どの条件で落ちたか」を構造化して返す。
3. **単位を型名に出す。** `_man`（万円）と `_yen`（円）を接尾辞で必ず区別する。
   この2つの取り違えが、この領域で最も起きやすい事故。
4. **未確認と不適合を分ける。** 電話では年収を聞かない（警戒されるため）。
   `None` は「条件を満たさない」ではなく「まだ聞けていない」として扱う。
5. **除外を先に評価する。** 勤続1年未満・転職検討中は、他が満点でも保留。
   加点式にすると、この絶対条件が埋もれる。

## モジュール構成

```
loan.py       ローン計算。全数値の一次情報源
screening.py  06 電話5問 → 仮ランク
rank.py       07 3軸 → 確定ランク
quadrant.py   09 年収×貯蓄の4象限（TYPE A-D）
```

`rank.py` は `loan.py` を使う。逆方向の依存はない。

## 検算済みの定数

すべて 35年・元利均等。実装は `loan.py` の1か所で定義する。

| 項目 | 値 | 前提 |
|---|---|---|
| 借入2,000万の月々 | 56,457円 | 実行金利1% |
| 借入500万あたりの月々 | 14,114円 | 同上。借入額に依存しない |
| 借入100万あたりの月々 | 2,823円 | 同上。頭金の効き方もこれ |
| 10年後のローン残高 | 1,498万 | 借入2,000万・120回返済後 |
| 年収400万の借入上限 | 2,823万 | 審査金利3.5%・返済比率35% |
| 同上・審査金利3.0% | 3,031万 | |
| 提案上限 | 借入上限 × 0.7 | 持ち出しを維持できる線 |

### 丸めについて

借入上限は **四捨五入**する。切り捨てにすると年収400万・500万・850万の3件が
資料の記載と1万ずれる。9冊に印刷済みの数字を正とした。

なお `2823` は「年収400万の借入上限（万円）」と「借入100万あたりの月々（円）」の
両方に出てくるが、**無関係な別の数字**である。単位が違う。混同しないこと。

### 提案金利と審査金利は別物

`max_borrowing_man()` は審査金利（3.0〜3.5%）で計算する。
`monthly_payment_yen()` は実行金利（1%）で計算する。
**この2つを同じ金利で計算してはいけない。** 実行金利で上限を出すと
年収400万で4,133万・年収の10.3倍が出て、事前審査で落ちる。

## 判定の仕様

### 仮ランク（screening.py）— 電話5問

電話では年収を聞かない。取れるのは家賃・勤続・転職転勤・同居家族・購入動機の5つ。

除外を先に評価する。

| 判定 | 条件 |
|---|---|
| 見送り | 家賃0円 **かつ** 購入動機なし |
| 保留 | 勤続1年未満 **または** 転職を検討中 |

除外に当たらなければ、4条件の充足数で決まる。

- 家賃がある（0円でない）
- 勤続3年以上
- 転職予定なし
- 決裁権者の同席が取れる
- 購入動機あり

| 仮ランク | 欠けている数 |
|---|---|
| A | 0 |
| B | 1 |
| C | 2以上 |

**これは仮である。** 確定ランクは年収・貯蓄・借入を取ってから `rank.py` で付け直す。

### 確定ランク（rank.py）— 3軸

| 軸 | 見るもの |
|---|---|
| 会える確度 | アポが成立するか |
| 属性の質 | 年収・貯蓄・借入。いくらの物件を提案できるか |
| 審査適性 | 勤続年数・既存借入。そもそもローンが通るか |

勤続年数を属性から独立させているのは、**性質が違うため**。
年収が高くても勤続1年未満なら金融機関が通さない。
営業力でも属性の良さでも埋まらない制度の壁なので、独立した軸にする。

| ランク | 条件 |
|---|---|
| 見送り | 家賃0円 かつ 購入動機なし |
| 保留 | 勤続1年未満 または 転職検討中 |
| S | 年収650万↑ / 借入なし / 勤続3年↑ / 決裁権者の同席可 |
| A | 年収500万↑ / 借入なし / 勤続3年↑ |
| B | 年収350万↑ / 勤続1〜3年、または軽微な借入あり |
| C | 上のどれにも当てはまらないが、会える |

### 顧客タイプ（quadrant.py）— 年収 × 貯蓄

貯蓄150万が分かれ目。諸費用（物件価格の7〜10%）を自己資金で出せるかの線。

| | 貯蓄150万↑ | 貯蓄150万未満 |
|---|---|---|
| **年収500万↑** | TYPE A | TYPE B |
| **年収500万未満** | TYPE C | TYPE D |

資料では「年収350-450万」を低所得側としているが、450〜500万に隙間ができるため、
**実装では500万を境界とする**（資料側の表記揺れ）。

## 使い方

```python
from screening import PhoneAnswers, provisional_rank
from rank import CustomerProfile, final_rank
from loan import max_borrowing_man, proposal_cap_man, monthly_payment_yen

# 電話の直後
print(provisional_rank(PhoneAnswers(
    rent_yen=60000, tenure_years=5, job_change=None,
    decision_maker_present=True, has_motivation=True,
)).rank)          # -> A（仮）

# 在宅で属性が取れたあと
r = final_rank(CustomerProfile(
    annual_income_man=650, savings_man=200, tenure_years=9,
    existing_debt_monthly_yen=0, rent_yen=70000,
    decision_maker_present=True, has_motivation=True,
))
print(r.rank, r.reasons)
```
