# SCREEN_SPEC — 画面仕様

UI の実装は Phase 9（Next.js PWA）。**現在あるのは画面に依存しない表示ロジック `packages/workspace` だけで、画面そのものは NOT IMPLEMENTED。**
API（Phase 2・3・7）ができる前に画面だけを作り込まない（No Fake UI）。最初に高精度で作るのは Dashboard・Lead List・Call Workspace・Outcome・Follow-up。

## 2. Call Workspace（最重要）

### レイアウト（Desktop ≥ 1280px）
```text
┌───────────────────────────────────────────────────────────────────────────┐
│ 山田 太郎 ・ 山田工務店 ・ 新築キャンペーン ・ +81 90-****-5678              │
│ ● お客様が話しています（文字+アイコン+色）  02:31   担当: AI → [引き継ぐ T] │
├────────────────┬────────────────────────────────────┬─────────────────────┤
│ 顧客の文脈      │ 会話（文字起こし）                   │ AI アシスト          │
│ ・前回の通話    │ お客様  ……                          │ 状態: 資料を確認中    │
│ ・前回の結果    │ AI      ……                          │ 提案された返答（送信しない）│
│ ・フォロー予定  │ あなた  ……                          │  └ なぜこの提案？     │
│ メモ（自動保存）│ ┄ 認識中 ┄（確定前は薄く・斜体）     │ ナレッジ検索          │
│                 │ [会話内を検索]                       │ 次の一手              │
├────────────────┴────────────────────────────────────┴─────────────────────┤
│ [ミュート M]  [引き継ぐ T]  [転送]                          [通話を終了]   │
└───────────────────────────────────────────────────────────────────────────┘
```
- 1024px：右列を折りたたみ（タブで切り替え）。768px 以下：1カラム（状態 → 顧客 → 文字起こし → 下部固定の操作バー）
- ヘッダーは常に見える（スクロールしない）：顧客・会社・キャンペーン・電話（マスク）・通話状態・経過時間・担当（AI / 人）

### 通話状態の表示（`callIndicator`）
文字ラベル・アイコン・色を必ずセットで出す（色だけにしない）。読み上げ用に `aria-live="polite"`、切断は `assertive`。

| 状態 | ラベル | 備考 |
|---|---|---|
| REQUESTED / DIALING | 発信準備中 / 発信中 | |
| RINGING | 呼び出し中 | |
| IN_PROGRESS（担当 AI） | AI が話しています / お客様が話しています / お客様とつながりました | 直近の話者で切り替え |
| IN_PROGRESS（担当 人） | あなたが対応中 | 引き継ぎ後に AI の発話イベントが届いても表示しない |
| 通話中に接続が切れた | 接続が切れました | **画面全体の警告（blocking）**。トーストにしない。「表示は最後に受信した時点のもの。AI の操作は止めています」＋再接続 / 通話を終了 |
| ENDED / FAILED / NO_ANSWER / BUSY / CANCELED | 通話終了 / 発信失敗 / 応答なし / 話し中 / 発信取り消し | 通話後の切断は警告にしない |

### AI の状態（`aiActivityView`・`aiConfidenceNotice`）
聞いています・考えています・話しています・資料を確認しています・空き日程を確認しています・担当者への引き継ぎを準備しています・待機しています。
人が引き継いだ後は「停止中（あなたが対応中）」。確信度は低いときだけ「人の確認をおすすめします」（不明な値は低いものとして扱う）。

### 引き継ぎ（Take Over）
- 常に同じ位置（ヘッダー右と下部バー）。キーボード `T`（文字入力中・変換中は無効）
- 押した瞬間「引き継いでいます…」→ 成功「あなたが通話中です。AI は停止しました」。失敗時は AI を再開せず「引き継げませんでした。AI は停止したままです。もう一度引き継ぐか、通話を終了してください」
- 確認ダイアログは出さない（即時）

### 通話を終了
- 緊急停止を兼ねるので**確認なしで即時**（`confirmationFor("END_CALL") = IMMEDIATE`）。誤操作は位置（右端・他のボタンと離す）で防ぎ、1文字ショートカットは割り当てない

### 提案された返答・ナレッジ
- 「提案された返答」と明示し、**自動で送らない**。「なぜこの提案？」で根拠（参照したナレッジ）を表示
- ナレッジ検索は通話から離れずに（製品・価格・FAQ・反論・ポリシー）。ナレッジにないことは「資料に記載がありません」と出す

### メモ・履歴
メモは入力中に自動保存（失敗したら入力欄の下に「保存できませんでした。入力内容は残っています」）。顧客の文脈列に前回の通話・結果・メモ・フォロー・アポ。

## 3. Outcome（通話後）
- 現行の5ボタン（成約・検討・折り返し・不在・拒否）を先頭に固定し、拡張分（アポ確定・番号違い・留守電）は「その他」に畳む（`outcomeButtons`）
- 選んだら次にやることを出す（`nextStepFor`）：折り返し → 日時（必須）／アポ確定 → 日時（必須）／検討 → フォローアップの期日（提案、変更可）／拒否・番号違い → 発信禁止の確認／成約・不在・留守電 → 追加入力なし
- 結果とメモは1回の保存で送る。保存に失敗しても入力内容を消さない（`errorCopy("OUTCOME_SAVE_FAILED")`）
- 保存後は「次の相手」を表示する。**発信は人が押す**（自動発信は `AUTO_DIAL_ENABLED` の別機能）

## 4. 発信禁止（DNC）の表示（`suppressionBanner`・`canOfferCall`）
- 普通のタグではなく、顧客の全画面で最上部のバナー：「発信禁止 — 今後、この相手には発信できません。」
- 保存中・保存失敗・状態不明のときも発信ボタンを出さない（fail-safe）。失敗時は「発信禁止を保存できませんでした — 確認が終わるまで、この相手への発信は止めています。［もう一度保存する］」
- 解除は Admin のみ・強い確認（対象名の入力）・監査に残る（`describeConfirmation("REMOVE_DNC")`）
- 画面の判断は表示だけ。最終的な可否は必ずサーバー（`CreateCallUseCase`）が判定する

## 5. 発信ボタン
- 連打しても要求は1件（`CallStarter`：応答待ちの間は重複扱い）。タイムアウトで発信されたか不明なら、**同じ冪等キーを持ち続け、自動では再発信しない**（`errorCopy("CALL_START_UNKNOWN")`）
- 楽観的 UI にしない（発信・発信禁止・成約・転送・削除はサーバーの確定を待つ）

## 6. Follow-ups
期限切れ・今日・今後・完了（`bucketFollowUps`、組織のタイムゾーンの日付で判定）。期限切れは赤を乱用せず、件数＋アイコン＋文言（「期限切れ 3件」）で示す。List を既定、Calendar は切り替え。

## 7. Lead List
- 列：名前・会社・電話（マスク）・スコア・状態・キャンペーン・最終接触・次の一手・担当。列の表示/並びはユーザーが調整（ブラウザに保存）
- スコアは数字だけにしない：「92 優先度高」＋理由（`scoreLead().explanation`：直近の問い合わせ・条件一致・未接触 など）
- 次の一手：今すぐ発信 / フォロー / 確認 / 日程調整 / 発信禁止（`decideNextAction`。抑止中は常に発信禁止）
- 検索（名前・会社・電話・メール・キャンペーン・タグ）と絞り込みは**サーバー側**。有効な絞り込みは常にチップで表示。保存ビュー（今日かける・高スコア未接触・折り返し待ち・今週の見込み客）
- 1万件以上でも全件を取らない。カーソルページング。仮想スクロールは計測してから

## 8. Settings と危険な操作
- 項目ごとに分ける：組織・ユーザー・ロール・電話・AI・キャンペーン・コンプライアンス・連携・請求・セキュリティ
- **Danger Zone**（Owner のみ）：自動発信・録音・発信そのもの・組織の削除・API の認証情報
- 確認の強さ（`confirmationFor`）：

| 操作 | 強さ |
|---|---|
| 通話を終了・メモの保存・発信 | 即時 |
| スキップ | 取り消し（Undo） |
| 発信禁止に登録・転送・全発信を停止 | 確認（何を・誰に・どうなるか） |
| 発信禁止の解除・全発信の停止を解除・自動発信 ON | 強い確認（対象名を入力）。Undo に頼らない |

- 全発信停止（STOP ALL OUTBOUND CALLS）：管理者の画面上部に常に状態を表示。停止は確認1回、解除は強い確認
- 権限のない機能は、場合に応じて 非表示 / 無効（理由をツールチップ）/ 読み取り専用。**セキュリティは API で強制**
- 重要操作の後は管理者が「誰が・何を・いつ」を監査ログで追える

## 10. キーボード（`resolveShortcut`）
⌘K / Ctrl+K：コマンドパレット（入力中でも）／`/`：検索／Esc：閉じる／通話中のみ M：ミュート・T：引き継ぐ（AI 担当中だけ）・N：メモ・F：フォローアップ。
文字入力中・日本語の変換中・修飾キー付きでは1文字ショートカットを発動しない。通話終了には割り当てない。

## 11. E2E（Playwright、Phase 9 以降）
1. ログイン → Dashboard → リード → 発信（Mock）→ 通話 → 引き継ぎ → 終了 → 結果 → フォローアップ
2. 発信 → 拒否 → 発信禁止の表示 → 再発信を試す → **UI と API の両方が拒否**
3. 発信ボタンの高速連打 → 外部発信 1 件
4. AI 障害 → オペレーターに警告 → 引き継ぎ → 安全に継続
5. 通話中のリロード・複数タブ・ブラウザを閉じる → サーバーの通話状態が壊れない
6. キーボードだけで 1 と 2 を完了できる。axe で重大な違反 0
