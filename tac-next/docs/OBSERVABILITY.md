# OBSERVABILITY — ログ・メトリクス・トレース・アラート

**状態：NOT IMPLEMENTED**（Phase 15。新しい重要なワークフローを作るときは、その変更の中でログ・メトリクス・トレースも足す）。

## 相関 ID（すべてのログ・トレースに付ける）
`request_id`・`trace_id`・`organization_id`・`campaign_id`・`contact_id`・`call_id`・`conversation_id`
電話番号は末尾4桁だけ（`maskE164`）。会話の本文・トークン・Cookie・キーはログに出さない。

## メトリクス
発信の要求・開始・接続・失敗・**抑止による拒否**・DNC 登録・引き継ぎ・プロバイダ/AI/Webhook のエラー・キューの深さ・遅延（音声 p95）・コスト。

## アラート（重さを分ける。すべてを Critical にしない）
| 重さ | 条件 |
|---|---|
| Critical（即時に人を起こす） | 想定外の発信の急増／抑止中の番号への発信試行がサーバーに到達／抑止サービスの照会失敗が続く／コストの急増 |
| High | プロバイダ・AI の障害率／Webhook の署名不正の急増／キューの滞留 |
| Warning | 遅延の悪化／再試行の増加 |

## 1通話を端から追えること（Phase 15 の完了条件）
発信要求 → ポリシー判定（理由）→ プロバイダの発信 → Webhook → 会話 → 結果 → フォローアップ を `call_id` で辿れる。
