# COMPLIANCE — 法令対応の設計（M）

> **重要**：この文書は設計上の要件であり、法的助言ではありません。対象地域・商材・取引の相手（事業者か消費者か）で
> 必要な対応が変わります。**本番利用の前に、弁護士など専門家の確認を必ず受けてください。**

## M. 設定できるポリシー

法的な判断を AI に確定させない。判断はポリシー（設定値＋コード）で行い、AI は検知と提案だけをする。

| ポリシー | 内容 | 日本向けの初期値 |
|---|---|---|
| `DisclosurePolicy` | 応答直後に告げる項目 | 事業者名・担当者名・商品の種類・勧誘目的（特定商取引法の電話勧誘販売での明示義務を想定）。項目が1つでも欠けていたら発信できない |
| `SuppressionPolicy` | 断られた相手への再勧誘の禁止 | 「拒否」「もう電話しないで」等で即時に抑止。解除は本人からの再連絡希望があったときだけ、Admin が理由を添えて行う |
| `CallingWindowPolicy` | 発信できる時間帯 | 相手のタイムゾーン（不明なら組織のタイムゾーン）で 9:00〜20:00、日曜・祝日は不可（組織で変更可） |
| `ConsentPolicy` | 同意が必要な場面 | AI 音声で話す発信は、有効な同意がある相手に限る（ADR-0003）。人による発信は同意を必須にしない |
| `RecordingPolicy` | 録音 | 既定 OFF。ON のときは冒頭で録音を告知し、`recording_consent` を記録する |
| `RetentionPolicy` | 保存期間 | 文字起こし・録音は既定 90 日で自動削除。監査ログは 5 年 |
| `RateLimitPolicy` | 掛けすぎの防止 | 同じ番号には 1 日 1 回まで。不在の再試行は最大 3 回で、間隔は 1 日以上あける |

## 個人情報の保護（日本の個人情報保護法を想定）
- 利用目的を組織の設定に明記し、取り込み時の取得元（`lead_sources`）を記録する。
- 本人から開示・訂正・利用停止の求めがあれば `PRIVACY_REQUEST` として扱い、抑止とあわせて対応タスクを作る。
- 個人データの保存場所（リージョン）を記録する。Fly の nrt（東京）を既定にする。

## 記録（監査に耐えること）
- 発信ごとに、時刻・発信者・相手・キャンペーン・名乗った内容・結果・抑止の有無を残す。
- 発信を止めた場合も（抑止・時間外・上限・名乗りの設定不足）、`blocked` として理由つきで記録する
  （現行の Call Log の良い点を引き継ぐ）。
